# 机器人自动回充控制板：脱敏项目案例

> 本文只描述个人承担的工程工作和通用方法，不包含实习单位的原理图、PCB、内部协议、器件清单、产品尺寸或完整控制策略。

## 项目背景

机器人需要在回桩过程中识别机构到位状态，并由充电基座下位机完成状态采集、控制判断、异常保护与整机联调。项目同时涉及嵌入式软件、外围设备通信和充电控制板硬件开发。

## 个人工作

- 基于 ESP32-C3 参与下位机控制程序开发，围绕回桩和机构到位状态整理控制流程。
- 完成外围设备驱动和通信调试；结合程序 Debug、通信状态检查和分模块替换定位数据交互异常。
- 使用中断与定时器完成板级信号检测及相关控制逻辑，参与功能验证和整机联调。
- 参与控制板从需求分析、器件选型、原理图到 PCB Layout 的完整开发流程。
- 使用示波器和万用表进行多批次板卡测试，围绕过流保护、静电防护和电源纹波进行问题定位与优化。

## 工程方法

### 1. 先定义状态与故障边界

把“未连接、对接中、已到位、允许充电、充电中、故障”等状态及其进入条件、退出条件、超时条件写清楚，再实现状态转换。这样可以降低多个输入信号同时变化时的逻辑耦合。

### 2. 分层定位通信问题

从供电与电平、物理连线、总线时序、设备地址、寄存器/帧格式到应用状态逐层检查。通过最小读写用例和固定测试数据，区分硬件连接、底层驱动与业务逻辑问题。

### 3. 软件与硬件联合验证

程序断点只能说明软件路径，示波器波形才能确认真实时序与电气状态。调试时将关键状态映射到日志、GPIO 或可观测变量，并与电源纹波、控制信号和通信波形对齐分析。

### 4. 让异常路径可恢复

对通信超时、信号抖动、状态不一致和上电初值设置明确的降级或复位路径，避免控制流程永久停留在中间状态。

## 可迁移能力

这个项目体现的重点不是某一块特定产品板，而是软硬件协同能力：把需求转换为状态机和接口，完成驱动与板级调试，并用可测量的证据定位系统问题。
